The Opportunity

stripe-java powers millions of businesses.
Its infrastructure code deserves deeper coverage.

Bug - Open

ClassCastException shadows API errors

Issue #1846 — When the API returns a non-JSON error, users get an uninformative ClassCastException instead of a proper StripeException. Open since August 2024.

Bug - Open PR

NumberFormatException in webhook parsing

PR #2149 — Malformed webhook timestamps cause unhandled exceptions. Community PR submitted January 2026, still open.

Feature - Requested

Micrometer / OpenTelemetry instrumentation

Issue #1964 — Enterprise users need observability hooks for API calls. Workaround requires wrapping the entire library.

Feature - 5 upvotes

GraalVM Native Image support

Issue #1905 — Increasingly critical for Quarkus, Micronaut, and Spring Native users. No official reachability metadata.

Devin × Stripe 06
The Challenge

SDK engineers are stretched between
generated code and infrastructure quality

stripe-java's codebase is primarily auto-generated from Stripe's OpenAPI spec. The hand-written infrastructure layer — networking, serialization, error handling, webhook verification, retry logic — is where real bugs originate.

With SDK engineers focused on API version releases and code generation, infrastructure improvements accumulate in the backlog. Some issues have been open for 18+ months.

24 open issues

Including bugs that affect production error handling and feature requests with significant community demand.

~30 hand-written files

Core infrastructure code (networking, GSON adapters, webhooks, telemetry) that would benefit from deeper unit test coverage.
